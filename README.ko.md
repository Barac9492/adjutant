프레임워크가 아닙니다. 포크해서, 설정하고, 당신 것으로 만드세요.*

## 이게 뭔가

7개의 스케줄 에이전트, 당신의 미해결 결정에 대해 논쟁하고 지난번에
뭐라고 했는지 기억하는 3인 어드버서리얼 보드(Adversarial Board), 같은 결정을
영원히 재분석하지 못하게 막는 결단 원장(Decision Ledger), 그리고 이 모든 걸
유지보수 가능하게 만드는 바벨 파이프라인(저렴한 모델이 정찰 → 최고 모델이
계획 → 저렴한 모델이 구현 → 새로운 시선의 리뷰). 전부 표준 Claude Code
위에서 돌아갑니다 — 새 런타임도, 가입해야 할 서비스도 없습니다. 클론하고,
마법사 하나 실행하면, 커피 한 잔 마실 시간에 작동하는 시스템이 생깁니다.

## 왜 설치가 아니라 포크인가

이건 `npm install` 하고 잊어버리는 라이브러리가 아닙니다. dotfiles에 가깝습니다:
읽고, 필요 없는 걸 잘라내고, 당신 삶에 맞을 때까지 나머지를 구부리도록
만들어졌습니다. `/setup` 마법사가 몇 분 안에 작동하는 기본값을 만들어줍니다;
그 이후는 전부 당신이 빚는 겁니다.

## 빠른 시작

```bash
git clone <this-repo> adjutant && cd adjutant
./install.sh
```

이후 이 디렉토리에서 Claude Code를 열고:

```
/setup
```

온보딩 마법사입니다 — 이름, 시간대, 노트가 어디 있는지, 어떤 결정을 안고
있는지, 어떻게 알림받고 싶은지를 인터뷰하고 `config/os.config.yaml`을
작성합니다. 이 저장소의 다른 어떤 파일도 개인 데이터를 다른 곳에서 읽지
않습니다 — 그 파일 하나가 "제네릭 템플릿"과 "당신의 설정" 사이의 유일한
경계선입니다.

설정 직후 `/today`나 `/decide list`를 실행해보세요 — 설정할 게 산더미처럼
남은 게 아니라 몇 분 안에 실제 결과물을 보게 될 겁니다.

## v1에 들어있는 것

| 구성요소 | 하는 일 |
|---|---|
| `/board convene` | 도메인 베테랑, 다운사이드 방어 목소리, 실행 책임 목소리 — 세 명의 상설 비평가가 당신의 미해결 결정에 대해 논쟁하고, 지난번 말한 걸 기억합니다. |
| `/decide` | 미해결 고위험 결정을 추적하고, 이미 미루고 있는 결정에 대한 새 분석 요청을 거부하며 대신 리뷰를 강제하는 결단 원장. |
| `/briefing`, `/today` | 노트 볼트를 현재 상태 요약이나 오늘의 우선순위 계획으로 변환. |
| `briefing-morning`, `followups`, `meeting-prep`, `email-triage`, `orchestrator`, `weekly-synthesis`, `health-check` | 스케줄 가능한 에이전트들 — `os/skills/` 참고. `email-triage`는 분류와 초안 작성만 하며 절대 대신 발송하지 않습니다. |
| `os/CLAUDE.md` | 다른 모든 구성요소가 전제하는 바벨 파이프라인과 딜리버리 게이트. |
| `os/agents/delivery-critic.md`, `persona-qa-player.md` | 새로운 시선의 게이트: 하나는 당신에게 보이기 전에 결과물을 리뷰하고, 다른 하나는 당신이 URL을 열기 전에 지정된 페르소나로 배포된 앱을 직접 플레이합니다. |

전체 추출 근거는 `docs/ARCHITECTURE.md`, 재사용 가능한 엔지니어링 패턴은
`docs/patterns.md`를 참고하세요.

## 이게 당신에게 필요로 하는 것

- **스케줄러.** 이 저장소는 "무엇을"만 제공하고 "언제"는 제공하지 않습니다 —
  Claude Code 스케줄 태스크, cron, 또는 이미 쓰고 있는 도구를 연결하는
  방법은 `docs/cookbook/scheduling.md`를 참고하세요.
- **유지보수에 대한 정직함.** 포크하고 손을 놓아도 괜찮습니다 — 이제
  당신 것이니까요. 기여하고 싶다면 `ROADMAP.md`와 `CONTRIBUTING.md`를
  확인하세요.

## 이 저장소를 당신의 분야에 맞게 바꾸기

`examples/verticals/`에 보드와 원장을 특정 도메인에 맞게 재조정한 예시가
하나 있습니다 (현재: 벤처캐피털 — `vc.md`). 더 많은 버티컬 예시는 PR로
환영합니다 — `CONTRIBUTING.md` 참고. 보드의 베테랑 좌석이 커스터마이징하기
가장 좋은 부분입니다 — 설정의 `board.veteran.domain` 필드 하나만 바꿔도
대부분의 효과를 얻습니다 (필드 하나로 얼마나 달라지는지는 `vc.md` 참고).
그 이상 — 단순히 다른 관점이 아니라 완전히 다른 목소리 — 를 원한다면
`os/agents/board-veteran.md`의 페르소나 노트를 직접 다시 쓰세요.
